# Risiken wenn man nicht strukturiert vorgeht in einem Projekt

- Ein Produkt wird realisiert, bevor das vom Auftraggebeer erwartete Ergebnis klar ist.
- Wichtige Umsetzungsaufgaben bzw. -tätigkeiten werden vergessen.
- Dokumente, die für die Nutzung oder Weiterentwicklung des Produkts wichtig sind, werden gar nicht oder zu spät erstellt.

Beispiel: 
Eine Anwendung wird programmiert bevor klar ist was die Benutzer genau wollen. Danach muss soviel angepasst werden das so viel Aufwand aufkommt wie beim ersten Realisierungsprozess.

# Elemente von Vorgehensmodellen

Mithilef eines **Vorgehensmodell** kann der **Realisierungsprozess** effizient und in einzelne **Phasen** zerlegt werden. Jede Phase endet mit einem **Meilenstein**.

Elemente eines Vorgehensmodells:

| Element     | Beschreibung                                                                                                    | Beispiele                   |
| ----------- | --------------------------------------------------------------------------------------------------------------- | --------------------------- |
| Phase       | Zeitabschnitt indem ein Teilprozess ausgeführt wird und bestimmte Ergebnisse erarbeitet werden.                 | Anfoderungsanalyse          |
| Meilenstein | Ende einer Phase. Bestimmte Ergebnisse werden von der Phase erwartet.                                           | Spezifikation abgenommen    |
| Aktivität   | Konkrete Aufgabe / Tätigkeit während einer Phase. Aktivitäten beziehen sich immer auf eine konkrete Ergebnisse. | System abgrenzen            |
| Ergebnis    | Erwartetes Lieferobjekt einer AKtivität oder Phase.                                                             | Dokumente oder Programmcode |
| Rolle       | Funktionale Beschreibung der Personen die an der Phase oder Aktivität beteiligt sind.                           | Business-Analyst            |
(Ein Business Analyst hat die Aufgabe, Anfoerdrungen und Wünsche der Kunde aufzunehmen und so darzulegen das es sich für die Systementwicklung eignet)
